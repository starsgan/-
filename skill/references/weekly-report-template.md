# 产品组员周报填写要求与模板

## 一、填写与提交方式

组员按本模板提交个人周报，由组长统一合并形成部门周报。周报用于了解实际工作进展、投入及风险，也为后续季度成果汇总提供材料。

- **按事项填写，不按每天的流水账填写。** 覆盖本周实际开展的项目交付、内部产品研发、销售支撑（含POC）及其他独立工作。
- **每人填写本人承担的工作、成果和实际工时。** 多人协作时说明本人负责的部分，不将整个团队成果写为个人独立成果，不代填其他人的工时。
- **同一事项、同一版本／期次，一人每周一条。** 调研、设计、搭建、调优、演示等相关工作合在同一条内，按1、2、3分项说明；一期、二期或明确的大版本分别列项，小版本可合并说明。
- **多人参与同一事项，各自使用一致的事项名称和版本／期次。** 组长按事项合并工作、进展与计划，并汇总本组实际工时。
- **按统一报告周期提交。** 具体提交时间和渠道由组长通知。发现可能影响交付的风险或阻塞，应及时同步组长，不等周报时才反馈。

## 二、每个字段怎么写

### 1. 事项名称

使用实际项目、产品或商机名称，沿用季度报告及组内已统一的名称，跨周保持一致。

- 不使用“产品工作”“客户支持”“其他”等无法识别具体事项的名称。
- 不把同一项目的客户简称、船名、产品名分别作为多个项目重复填写。
- 新事项或归属不清的事项，在提交时标注待确认，由组长统一名称和归属。

### 2. 版本／期次

填写“一期”“二期”“V1.1”或明确的迭代名称。无明确分期的项目可填“不分期”；无版本的售前支撑等事项填“—”。

同一轮方案即使曾有不同叫法，也应使用组内确认后的统一名称，不因改名重复列项。后续版本只做了规划的，要在进展中明确为规划成果。

### 3. 具体工作内容

**写本周实际开展了什么工作。此处与季度报告中的工作目标不同，不填长期目标或整季度任务。**

- 按1、2、3分条，写清动作和对象，例如“梳理岸端告警处理流程”“调整检修记录页面及交互”“开展图纸提取效果验证”。
- 本列不写完成程度、评审结论、客户确认或上线状态，这些统一写入“本周进展”。
- 避免只写“跟进项目”“参加会议”“持续优化”。会议应说明讨论的具体内容；有结论或待办的，在进展中说明。
- 同一事项包含多种工作时合在一条内，不必按需求调研、产品详设、UI设计、智能体开发等小类拆行。

### 4. 人员与实际工时

统一格式：**本人承担的主要内容，Xh。**

- 只填本人本周实际投入，不填预计工时；可以填写小数，不要求凑成固定周工时。
- 同一笔工时只归入一个事项，不能同时计入客户项目、产品建设和资产沉淀。
- 如同一次工作同时支撑项目交付和通用能力建设，应说明复用关系；确有独立投入的，按实际工作分别记录。
- 组员不填写团队工时合计，由组长汇总。仅有下周计划、本周未开展的事项填0h。

### 5. 本周进展

**写本周形成了什么、目前到哪一步、还有什么未完成。** 多项工作按1、2、3分条，尽量与工作内容对应。

- 优先写可识别的成果，如方案、PRD、功能清单、原型、可运行Demo、验证结论、交接材料，以及这些成果当前的确认状态。
- 写清必要的范围和环境，例如“核心流程已在本地验证”“已上线Demo环境”“已提交客户，待确认”。
- 区分已编制、已提交、已评审、评审通过、客户确认、已上线、已验收。完成演示或内部测试，不等于生产上线或客户验收。
- 未完成或较上周无新增进展的，直接说明当前状态、未完成部分及原因，不重复抄写往周成果作为本周新增成果。
- 以业务成果和阶段结论为主。技术细节、样本数量和中间过程，仅在影响效果判断、验收或风险时保留；必要时附成果链接或存放位置。

### 6. 风险提示

无风险明确填“无”。存在已发生的阻塞、延期可能、效果不达预期或需要协调的问题时，按以下内容填写：

**问题／风险 → 可能影响 → 已采取或拟采取的措施 → 需要谁在什么时间提供什么支持。**

- 客户资料缺失、外部接口未就绪、关键评审未安排等影响推进的问题，应在本列明确列出。
- 不能在进展中写“因资料缺失无法验证”，风险却填“无”。
- 常规问题已有负责人和修复安排，且不影响计划的，可在进展中说明，风险填“无”；如可能影响后续节点，则应列为风险。

### 7. 下周计划

统一写清：**负责人、准备开展的工作、预期结果、预计完成时间。**

- 计划承接当前进展和未完成项，不只写“持续推进”“继续优化”。
- 需要客户资料、技术配合或外部确认的，同时说明依赖及所需时间。
- 无后续工作填“—”。
- 仅有下周安排、本周尚未开展的事项也可列入：工作内容填“—”，工时填0h，进展填“本周未开展”，下周计划正常填写。

## 三、两类事项如何归入

### 本周事项

具体项目、产品或商机的工作放入此表，包括项目交付、内部产品研发和销售支撑（含POC）。同一事项涉及不同类型的工作，仍按事项集中填写。

涉及新增功能开发的POC，应写清需求、设计、搭建和调优工作；基于已有产品的配置演示，应如实写场景配置、演示和答疑，不写成新增产品研发。

### 其他事项

未归入具体项目、产品或商机的独立工作放入此表，如公司视觉与物料、可复用资产沉淀、知识分享、新人带教及临时专项。使用实际事项名称，一项一条；没有则填“无”。

已计入具体项目的原型、交付文档、客户培训、项目协调等，不再以“其他事项”重复填写。只有另外开展了独立整理、改造或推广工作，才单列相应的资产沉淀或分享事项。

## 六、提交前自查

- 事项名称和版本是否统一，同一事项是否存在重复拆行？
- 工作内容是否写本周实际动作，成果与状态是否集中写在“本周进展”？
- 是否写清本人贡献，实际工时是否无重复、无预估冒充实际？
- 是否区分规划、Demo、验证、上线与验收，未完成部分是否如实说明？
- 阻塞、延期可能及协调诉求是否已逐事项写明？
- 下周计划是否包含负责人、预期结果和日期，依赖条件是否清楚？

**工时用于了解投入和安排资源，不直接换算价值分。周报提供成果线索，季度考核仍按事项成果和实际进展核分。**
